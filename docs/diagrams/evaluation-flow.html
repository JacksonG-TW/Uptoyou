Up to you — AI evaluation

A frozen 200-name set, a pgvector crib of worked examples, four candidate models — and a report that carries the set's sha256 so two scores only compare when they should.

Frozen, stratified, and honest about its author

  • • 200 names, fixed seed, stratified over the three name layers with a floor of 30 — so a layer with 20 real examples still gets scored instead of vanishing into a pooled average.
  • • The labels were drafted by one frontier model and cross-checked by a second. That is recorded in labeled_by, because an example teaches, and a crib that taught the wrong thing has to be able to name its teacher.
  • • The set caught a prompt that read better and scored worse. That is the only thing a frozen set exists to do.

Retrieval, not fine-tuning

  • • Rejected: another prompt revision (measured, and it lost); rejected: fine-tuning (a weight change nobody can read back).
  • • Chosen: labeled example names embedded into pgvector, the five nearest handed over as worked examples — knowledge added as data, in a table you can query.
  • • The store is the frozen set, so the asked name is in it. Retrieval excludes it in the WHERE clause; without that, the round would measure the lookup rather than the classifier.

What the numbers do and do not say

  • • Two of three local models reach the hosted baseline with the crib; the third loses points to the same crib. The pairing of model and crib is a measured variable, not an assumption.
  • • Every score is pooled accuracy over n = 200 against one sha256. Change the set and the columns stop comparing — which is why the digest is printed rather than trusted.
  • • A score is agreement with a teacher model, not correctness. The distinction is in the report, not only in the code.
